# XTF 桌面界面（可选）

这是一个面向非技术用户的 **Tkinter 桌面界面**。它不重新实现同步逻辑，只负责：

1. 读取飞书 Base 链接、App ID / Secret
2. 读取目标表字段，自动标出公式、查找引用等只读列
3. 读取 Excel / CSV，自动检查列映射和唯一索引列
4. 生成严格 YAML v2 配置
5. 先执行 `--dry-run` 预览，再调用现有 `XTF.py sync` 正式执行

底层仍然是命令行和 [YAML v2 配置](../config.example.yaml)，界面只是包装层。

## 运行

### 方式一：双击启动（Windows）

双击：

```text
gui\launch_gui.bat
```

脚本会优先使用项目里的 `.venv\Scripts\pythonw.exe`，其次尝试 `pyw` / `python`。

### 方式二：命令行启动

```bash
python gui/app.py
```

如果使用项目虚拟环境：

```bash
./.venv/Scripts/python.exe gui/app.py
```

### 依赖

只需要项目已有的运行依赖：

```bash
python -m pip install -r requirements.txt
```

Tkinter 是 Python 标准库的一部分，不需要额外安装。Excel 读取使用项目现有的 pandas / OpenPyXL / Calamine 链路。

## 使用流程

1. **连接飞书**
   - 填写 App ID、App Secret
   - 粘贴 Base 链接，例如：
     `https://xxx.feishu.cn/base/<app_token>?table=<table_id>`
   - 点“解析”后，下方会加载**数据表下拉框**
   - 链接没有 `table=` 参数也没关系：直接在“数据表”下拉框里选，选中后会自动补全链接并读取目标表
   - 需要刷新列表时点“刷新列表”

2. **选择 Excel**
   - 选择 `.xlsx` / `.xls` / `.csv`
   - 选择工作表（可选）
   - 界面会显示预览、列名、非空/唯一统计
   - 只读计算列会自动取消勾选；其他列可以手动取消

3. **同步设置**
   - 默认推荐“只追加”
   - 只有存在**源/目标都唯一且非空**的列时，才会启用按 key 的模式
   - 没有唯一 key 时，界面会禁用“只新增缺失 key / 更新 + 新增 / 删除匹配后重建”
   - “覆盖 / 清空”属于危险模式，需要先勾选“显示危险模式”

4. **预览与执行**
   - 必须先生成预览；预览不会写入飞书
   - 预览会显示动作、数量、单位和风险
   - 危险计划要求输入“删除”才能执行
   - 执行后可以查看状态、接受数、读回确认数

## 安全设计

- **不把 secret 写进配置文件**：secret 只保存在内存中，通过 `XTF_APP_SECRET` 传给子进程。
- **可以从现有 `config.yaml` 载入 secret**：载入后界面只显示“已载入”，不显示原值；保存设置时也不会写回。
- **先预览再执行**：执行使用与预览完全相同的配置；设置变化后必须重新预览。
- **危险模式隔离**：覆盖/清空默认隐藏，必须显式勾选；执行时还要二次输入“删除”。
- **只读列自动排除**：公式、查找引用、自动编号、创建/修改时间、创建/修改人、附件等不会被写入。
- **底层 fail-closed**：配置、key、编码、权限或 snapshot 有问题时，CLI 会在写入前停止。
- **破坏性模式请先备份**：`overwrite` / `clone` 会删除远端数据。Base v3 的删除回读在真实环境中曾出现 `batch_get` 兼容问题（已修复并加入回归测试），但仍建议优先使用 `bitable_v1`，或先确认有可恢复的源数据。

## 当前限制

- 界面目前只支持**多维表格（Bitable）**。电子表格（Sheet）请使用命令行。
- 不支持查看历史任务队列；每次执行结束就结束。
- 不提供稳定的 Python SDK；界面只调用 CLI 和 JSON。
- 没有内置的定时任务；需要定时同步请使用 Windows 任务计划程序或 CI。

## 打包成 exe（可选）

界面本身可以用 PyInstaller 打包：

```bash
pyinstaller --noconfirm --onefile --windowed --name XTF-GUI gui/app.py
```

但注意：`XTF-GUI` 仍需要找到 `XTF.py` 或 `XTF` / `XTF.exe` 可执行文件来执行同步。最稳妥的做法是把界面和 XTF 一起分发，并保持目录结构：

```text
XTF/
├── XTF.py
├── core/
├── api/
├── xtf_cli/
├── config.example.yaml
└── gui/
    └── app.py
```

如果只分发打包后的 GUI，需要把 `XTF` 二进制放在 GUI 程序旁边，或修改 [gui/core.py](core.py) 中的 `cli_command()` 查找逻辑。

## 测试

界面逻辑中不依赖 Tk 的部分有独立测试：

```bash
pytest tests/test_gui_core.py -q
```

布局回归测试需要桌面环境，无显示设备时自动跳过：

```bash
pytest tests/test_gui_layout.py -q
```

它会断言：

- 操作按钮行永远在可视区域内，不会被窗口边缘裁掉
- 过长的表单内容进入滚动面板，而不是溢出
- 滚动面板的内层宽度跟随画布宽度
- 过长的索引列提示会换行，不会横向截断
- 事实摘要与风险提示分开，长度互不影响
- `base_v3` 与 `bitable_v1` 的布局完全一致

## 界面布局说明

- **步骤 3 的表单可滚动**：模式说明、索引列提示、模式摘要都会随内容变长，操作按钮固定在底部不参与滚动。
- **模式说明只显示当前选中项**：单行显示在单选按钮右侧，切换模式即更新。
- **事实与风险分两行**：第一行是客观信息（模式、同步列数、索引列），红色部分是风险提示（会删除什么、会清空什么）。
- **切换 API 后端不影响布局**：`base_v3` 与 `bitable_v1` 的界面完全一致，只影响底层读取方式。

## 常见界面问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 底部「生成预览」按钮看不到 | 窗口太小 | 放大窗口；表单区可滚动，按钮始终固定在底部 |
| 索引列提示显示不全 | 内容过长 | 提示会自动换行；也可滚动查看 |
| 「只新增缺失 key / 更新 + 新增 / 删除匹配后重建」是灰的 | 源数据和目标表没有共同且唯一、非空的列 | 只能使用「只追加」，或先在目标表创建并回填唯一键 |
| 切换到 `bitable_v1` 后字段列表顺序变化 | 两个 API 返回字段的顺序不同 | 不影响功能，字段名一致即可 |
| 「读取目标表」报 1254302 | 应用没有该表的角色权限 | 把应用添加为 Base 文档应用，或检查高级权限设置 |
| 「数据表」下拉框是空的 | 没解析链接、凭据不完整，或应用没有 Base 读权限 | 先点「解析」，再点「刷新列表」；检查 App ID / Secret 和文档协作者 |
| 换了 Base 链接后下拉框还显示旧表 | 输入框内容已变但还没解析 | 点「解析」；改动链接会自动清空旧列表 |

## 权限

与 CLI 完全一致：

- 自建应用
- Bitable：`bitable:app`，或 Base v3 的 `base:*` 细粒度权限
- 把应用添加为 Base 的文档协作者（建议“可管理”）
- 开通权限后发布应用版本

详见 [docs/使用说明.md](../docs/使用说明.md) 和多维表格 API 文档。
