# XTF 2.0 使用说明

> 适用版本：`2.0.0-rc1`  
> 适用入口：源码 `python3 XTF.py <子命令>`；发布包 `XTF <子命令>`（Windows 为 `XTF.exe`）  
> 本文是端到端操作手册。参数逐项说明见 [CONFIG.md](./CONFIG.md)，模式细节见 [SYNC.md](./SYNC.md)，Sheet 算法见 [SHEET.md](./SHEET.md)。

---

## 1. 先了解使用边界

XTF 2.0 的稳定公共契约只有四类：

```text
CLI 命令
YAML schema v2
JSON 输出
进程退出码
```

`SyncService`、`core.*`、`api.*` 都是仓库内部实现，**不提供稳定 Python SDK**。需要自动化集成时，请调用 `XTF ... --json` 并读取退出码，而不是直接 import 内部模块。

另外请明确：

- 当前是 `2.0.0-rc1` 候选版，真实飞书 UAT、正式 Release 和部署并不因本地测试或 CI 通过而自动完成。
- `--dry-run` 可以进行**远端只读**调用，但不会执行任何 Feishu mutation；它仍可能在本机创建 `logs/`。
- 本工具不提供跨请求事务、成功前缀自动回滚或中断任务自动恢复。
- 首次在非空生产资源上使用前，请先在隔离的 Base/Sheet 上验证。

## 2. 环境与安装

### 2.1 环境要求

- Python **3.10+**（CI 覆盖 3.10、3.11、3.12、3.13）
- 依赖见 `requirements.txt`，其中 pandas 限定为 `>=2.2.3,<3`

### 2.2 安装

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Windows Git Bash / CMD 可直接使用：

```bat
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe XTF.py --version
```

开发或本地验证还需要：

```bash
python -m pip install -r requirements-dev.txt
```

### 2.3 输入格式

| 格式 | 扩展名 | 状态 | 说明 |
|---|---|---|---|
| Excel 2007+ | `.xlsx` | 主要支持 | 优先 Calamine，必要时回退 OpenPyXL |
| Excel 97-2003 | `.xls` | 需要支持该格式的引擎 | OpenPyXL 不读取旧 `.xls` |
| CSV | `.csv` | 实验性 | pandas 读取，UTF-8 失败后尝试 GBK |

Excel 读取默认保留文本并拒绝空白/重复表头，不会让 pandas 自动改名。CSV 不建议作为生产等价格式。

### 2.4 换到另一台电脑

如果目标电脑是 Windows，复制项目后直接双击根目录的 `setup_and_run.bat`：

- 首次运行自动创建 `.venv`、安装 `requirements.txt` 并启动 GUI
- 之后启动会跳过安装，通常不到 1 秒
- 目标电脑需要 Python 3.10+，安装时勾选 **Add python.exe to PATH** 和 **tcl/tk and IDLE**

复制时**不要带上**：

```text
.venv/          换机器后不可靠，而且很大
.git/           只运行不需要
logs/           运行日志
config.yaml     含 secret
测试.xlsx        本地生产数据
```

只使用 CLI 的话，复制源码后执行：

```bash
python3 -m venv .venv
python -m pip install -r requirements.txt
python3 XTF.py sync --config config.yaml --dry-run
```

如果目标电脑不能安装 Python，需要在 Windows 上先用 PyInstaller 构建
`XTF.exe` 和 `XTF-GUI.exe`，再把两个文件一起分发；详见 [gui/README.md](../gui/README.md)。

## 3. 五分钟跑通

### 第 1 步：生成配置

```bash
# 多维表格目标
python3 XTF.py config init --target-type bitable --output config.yaml

# 电子表格目标
python3 XTF.py config init --target-type sheet --output config.yaml

# 多维表格到多维表格
python3 XTF.py config init --source-type bitable --target-type bitable --output config.yaml
```

`config init` 是**唯一**创建主程序配置的命令。目标文件已存在时会拒绝覆盖，需要显式加 `--force`。

### 第 2 步：填写资源标识和凭据

打开 `config.yaml`，至少填写：

- `auth.app_id`
- `source.file.path`（或 `source.bitable.app_token` / `table_id`）
- `target.bitable.app_token` / `table_id`（或 `target.sheet.spreadsheet_token` / `sheet_id`）
- `sync.index.column`（`by_key` 模式必填）

**不要把真实 secret 写入配置、示例、提交或日志。** 推荐通过环境变量提供：

```bash
export XTF_APP_SECRET='your-secret'
```

Windows PowerShell：

```powershell
$env:XTF_APP_SECRET = 'your-secret'
```

### 第 3 步：本地校验

```bash
python3 XTF.py config validate --config config.yaml
python3 XTF.py config show --config config.yaml
```

说明：

- `config validate` 会解析成完整运行时配置，因此**需要能拿到 `app_secret`**（CLI、`XTF_APP_SECRET` 或 YAML 之一）；刚由 `config init` 生成、secret 仍为 `null` 的模板会以退出码 3 失败。
- `config show` 会显示最终值和来源（`cli` / `yaml:...` / `env:XTF_APP_SECRET` / `default:...`），secret 与 token 会脱敏。

### 第 4 步：本地/远端自检

```bash
# 只检查 Python、依赖、Excel 引擎、配置和本地输入
python3 XTF.py doctor --config config.yaml

# 额外做只读认证与目标 metadata 检查；仍不执行 mutation
python3 XTF.py doctor --config config.yaml --network
```

### 第 5 步：生成精确计划

```bash
python3 XTF.py sync --config config.yaml --dry-run
python3 XTF.py sync --config config.yaml --dry-run --json
```

dry-run 与正式执行使用同一个 planner。请审阅：

- `requested_mode` / `effective_mode`
- `actions` 的 kind、count、unit、destructive、clears_values
- `warnings`
- 是否包含 `delete_records` / `clear_range`

公开计划是**不可重放**的 `PlanDocument`，不包含凭据、记录正文、mutation payload 或 snapshot precondition。

### 第 6 步：正式执行

```bash
# 非破坏性计划；建议显式启用写后读回确认
python3 XTF.py sync --config config.yaml --verify-remote-writes

# 自动化场景
python3 XTF.py sync --config config.yaml --dry-run --json > sync-plan.json
python3 XTF.py sync --config config.yaml --json
```

### 第 7 步：破坏性操作

`overwrite`、`clone`，以及 planner 生成的任何 `delete_records` / `clear_range` action，正式执行都必须显式授权：

```bash
python3 XTF.py sync --config config-clone.yaml --allow-delete
```

`clone` 配置必须**省略** `match_strategy`。`--allow-delete` 只授权本次命令按当前计划执行，不代表生产操作、Release 或部署授权。

## 4. 配置说明

### 4.1 优先级与发现

- `app_secret`：**CLI > `XTF_APP_SECRET` > YAML**
- 其他值：**CLI > YAML > target-specific defaults**
- 未传 `--config` 时，仅当当前目录存在 `config.yaml` 才自动发现；显式传入不存在的 `--config` 会失败。
- 主程序不接受旧 flat YAML，也不自动迁移 1.9 配置。

### 4.2 最小 Bitable 配置

```yaml
schema_version: 2

auth:
  app_id: cli_your_app_id
  app_secret: null          # 推荐用 XTF_APP_SECRET 提供

source:
  type: file
  file:
    path: data.xlsx
    sheet_name: null

target:
  type: bitable
  bitable:
    app_token: your_app_token
    table_id: your_table_id
    create_missing_fields: true
    api_backend: base_v3     # base_v3 | bitable_v1，不会自动 fallback
    user_id_type: open_id    # open_id | union_id | user_id

sync:
  mode: full
  match_strategy: by_key
  index:
    column: ID
    datetime_granularity: exact
    timezone: null
```

### 4.3 Sheet 目标示例

```yaml
target:
  type: sheet
  sheet:
    spreadsheet_token: your_spreadsheet_token
    sheet_id: your_sheet_id
    start_row: 1
    start_column: A
    value_render_option: null
    datetime_render_option: null
    scan_max_rows: 5000
    scan_max_columns: 100
    write_max_rows: 5000
    write_max_columns: 100
    validate_results: false
    protect_formulas: false
    verify_formulas: false
    formula_max_locations: 20
```

### 4.4 Bitable 到 Bitable 示例

```yaml
source:
  type: bitable
  bitable:
    app_token: your_source_app_token
    table_id: your_source_table_id

target:
  type: bitable
  bitable:
    app_token: your_target_app_token
    table_id: your_target_table_id
    api_backend: base_v3

sync:
  mode: full                 # 仅支持 full / incremental
  match_strategy: by_key     # 仅支持 by_key
  index:
    column: ID
    datetime_granularity: exact
    timezone: null
```

源表和目标表不能是同一张表。目标字段必须预先存在且类型兼容；XTF 不会复制 Base 结构、视图、权限、自动化、公式、附件或需要跨表 ID 映射的关联字段。

### 4.5 其他常用配置项

```yaml
sync:
  verify_remote_writes: false       # 默认 false；成功只代表服务端接受
  verify_timeout_seconds: 10.0      # 0-300；0 表示只读一次
  verify_interval_seconds: 0.5      # 0.05-60

conversion:
  strategy: base                    # raw | base | auto | intelligence

control:
  batch_size: 500
  rate_limit_delay: 0.01
  max_retries: 3
  advanced:
    enabled: false
    retry:
      strategy: exponential_backoff # exponential_backoff | linear_growth | fixed_wait
      initial_delay: 0.5
      max_wait_time: null
      multiplier: 2.0
      increment: 0.5
    rate_limit:
      strategy: fixed_wait          # fixed_wait | sliding_window | fixed_window
      window_size: 1.0
      max_requests: 10

output:
  log_level: INFO                   # DEBUG | INFO | WARNING | ERROR
```

Sheet 目标的默认 `batch_size` 为 1000、`rate_limit_delay` 为 0.1，以 `config init --target-type sheet` 生成的模板为准。

## 5. 同步模式与索引

### 5.1 模式矩阵

| 模式 | `match_strategy` | 已存在项 | 不存在项 | 删除授权 |
|---|---|---|---|---|
| `full` | `by_key` | 更新 | 新增 | 不需要 |
| `incremental` | `by_key` | 跳过 | 新增 | 不需要 |
| `incremental` | `append_only` | 不匹配 | 全部追加 | 不需要 |
| `overwrite` | `by_key` | 删除后重建 | 新增 | 需要 `--allow-delete` |
| `clone` | 省略 | 全部清除 | 全部创建 | 需要 `--allow-delete` |

固定规则：

- `full` / `overwrite` 只支持 `by_key`
- `incremental` 可选 `by_key` 或 `append_only`
- `append_only` 必须省略 index，且不能与 selective 同时使用
- `clone` 必须省略 `match_strategy`，不能与 selective 同时使用
- planner 不会因为目标为空、Sheet 缺少索引等运行时条件隐式切换成 clone

### 5.2 索引列规则

- `by_key` 的索引列必须唯一且非空。
- 本地空 key、本地重复 key、远端重复 key 都会在 mutation 前失败。
- 数字 key 使用无损十进制归一化；已经以高风险 `float` 进入程序的大整数会 fail closed。
- 日期时间默认 `exact`：本地无时区值按 UTC，写入和匹配都使用毫秒。
- 选择 `day` 时必须配置 IANA 时区（如 `Asia/Shanghai`），不能依赖宿主机本地时区。

### 5.3 注意事项：目标表原本没有索引字段

当 `create_missing_fields: true`（默认）且目标 Bitable 原本没有索引字段时，XTF 会创建该字段，并**跳过读取已有记录**，把全部源行作为新增写入。目标中已有记录不会按 key 匹配，可能形成“旧记录 + 新记录”并存。

建议：首次在非空目标表上使用 `full` 前，先手动创建索引字段并回填 key；或者先在空表上验证。

### 5.4 `full` 的写入语义

`full` 不是字段级 diff：

- file → Bitable：匹配记录会写入源行中的**非空字段**；源端空单元格不会清空目标已有值。
- file → Sheet：匹配行会写入选定列（含空值），可能清空目标单元格。
- Bitable → Bitable：只更新真实发生变化的字段，源端空值可作为清空写入，并产生 `clears_values` 警告。

如果需要“源端为空即清空目标”，请在 file → Bitable 场景中另行处理，或改用 Bitable 数据源。

## 6. 字段类型策略

| 策略 | 自动创建的字段类型 | 适用场景 |
|---|---|---|
| `raw` | 文本 | 数据完整性要求极高 |
| `base` | 文本 / 数字 / 日期 | 日常使用（默认） |
| `auto` | 在 base 上增加单选 / 多选（依赖 Excel 验证信息） | 标准化 Excel 模板 |
| `intelligence` | 文本 / 数字 / 日期 / 单选 / 多选 / 复选框 | 高质量数据、进阶用户 |

```bash
python3 XTF.py sync --config config.yaml --field-type-strategy base
python3 XTF.py sync --config config.yaml --field-type-strategy intelligence
```

字段类型策略只决定**缺失字段的创建类型**。目标已存在字段时，XTF 按目标字段类型做严格转换；无法无损转换的非空值会在写入前失败，而不是被静默丢弃或猜测。

## 7. 选择性同步

只更新指定列/字段，其他列保持不变。

YAML：

```yaml
sync:
  selective:
    enabled: true
    columns: ["薪资", "部门", "更新时间"]
    auto_include_index: true
    optimize_ranges: true       # 仅 Sheet：合并相邻列范围
    max_gap_for_merge: 2        # 0-50；0 表示不合并
    preserve_column_order: true
```

CLI：

```bash
python3 XTF.py sync --config config.yaml \
  --selective --column 薪资 --column 部门 --column 更新时间
```

规则与差异：

- `columns` 必须非空、不能有空白名或重复名。
- 关闭 `auto_include_index` 时，必须显式把索引列加入 `columns`。
- Bitable 在记录 payload 中只包含选中字段。
- Sheet 按列范围写入；`optimize_ranges` 可减少 API 调用，但不会跨越未选中的中间列。
- `clone` 不支持 selective；`append_only` 也不支持 selective。

## 8. Sheet 专项

### 8.1 起始位置与清空范围

`target.sheet.start_row` / `start_column` 只决定后续读写数据的**起点**，不会缩小 `clone` 的清空范围。`clone` 会按工作表网格属性清空整张工作表。

### 8.2 分块

Sheet 读写默认按 **5000 行 × 100 列** 的客户端分块上限切分，可通过 `scan_max_rows` / `scan_max_columns` / `write_max_rows` / `write_max_columns` 调整。分块失败时只保留已成功叶子范围；不会把部分完成报告成全部成功。

### 8.3 公式保护

```yaml
target:
  type: sheet
  sheet:
    protect_formulas: true
```

约束：

- 仅支持 `full` 模式，且必须配置非空 `sync.index.column`。
- 通过 `Formula` 和 `FormattedValue` 双读检测公式列；任一读取失败或状态无法确认时停止写入。
- 索引列本身是公式列时拒绝计划。
- 受保护的公式列不会被重写。

### 8.4 写后公式验证

```yaml
target:
  type: sheet
  sheet:
    verify_formulas: true
    formula_max_locations: 20
```

- 独立于公式保护，不会由 `protect_formulas` 自动开启。
- 只校验 typed receipt 能证明的成功写入范围；不会为新增行生成或复制公式。
- 使用 Sheet AI；只有 `success + has_more=false` 才算通过，`partial` 不放行。
- 扫描截断时会按范围组、行、列二分继续；单格仍截断、发现真实公式错误或达到有限客户端探测次数时停止。
- `formula_max_locations` 是单次公式扫描返回的错误位置上限。

公式验证失败不会回滚已经被服务端接受的数据，只会让本次同步以失败关闭。

### 8.5 读取选项

`value_render_option` / `datetime_render_option` 用于特殊读取场景，默认 `null`：

- `value_render_option`：`none` / `ToString` / `Formula` / `FormattedValue` / `UnformattedValue`
- `datetime_render_option`：`none` / `FormattedString`

普通同步通常不需要修改；公式保护会按自己的调用参数执行双读，不依赖共享客户端的全局选项。

## 9. 写入确认与结果语义

### 9.1 默认行为

`sync.verify_remote_writes` 默认 `false`：

- 默认成功只代表**服务端接受了写入请求**。
- 不等于目标已经显示预期值，也不等于业务数据正确。

需要确认时：

```bash
python3 XTF.py sync --config config.yaml --verify-remote-writes \
  --verify-timeout-seconds 10 --verify-interval-seconds 0.5
```

确认逻辑：

- 首次读回立即执行。
- 暂时读到旧值时只重试**读取**，不会重新 create / append / 清空。
- 超时窗口约束的是后续读取的调度，不是整个命令的硬超时；正在执行的 HTTP 请求仍有自己的超时。
- 超时退出码为 `7`，错误码 `XTF_E_CONFIRMATION_TIMEOUT`。这时应先读取目标状态，不要自动重跑整个任务。

### 9.2 状态含义

```text
success | noop | failed | partial | indeterminate
```

- `failed`：没有确认成功的 mutation，发生确定性失败。
- `partial`：已有确认成功前缀，后续发生确定性 mutation 或 verification 失败。
- `indeterminate`：任一已发送 mutation 的远端结果未知；先检查目标，不要盲目重放。
- best-effort 的样式、自动下拉等附加配置失败只产生 warning，不覆盖已确认的数据成功状态。

### 9.3 统计口径

JSON `summary` 中：

- `accepted_by_unit`：服务端接受的操作数
- `confirmed_by_unit`：读回确认的操作数
- `counts_are_operations: true`：计数是操作次数，不是去重后的业务记录数
- `confirmation_complete`：整体成功且所有 verification 均通过时为 true

记录、行、列、范围、字段的单位不同，不能直接相加。

## 10. JSON 输出与退出码

### 10.1 输出流

- **stdout**：最终 human 摘要，或 `--json` 时的单一 JSON document。
- **stderr**：进度、warning、诊断和错误。
- **文件**：`logs/xtf_{target}_{YYYYMMDD_HHMMSS}.log`，每次运行（包括 dry-run）都可能创建。

### 10.2 JSON envelope

`--json` 输出包含：

```text
schema_version, command, status, ok, dry_run, config_path,
source, target, requested_mode, effective_mode,
plan, applied, verification, warnings, error, duration_ms, result
```

- dry-run 的 `status` 为 `planned`。
- 失败时仍需结合 `error.kind` 和退出码判断类别。
- 配置中的 secret/token 会在输出中脱敏。

### 10.3 退出码

| 退出码 | 含义 |
|---:|---|
| `0` | success / noop / dry-run 成功 |
| `1` | 内部运行时错误 |
| `2` | CLI 用法错误 |
| `3` | 配置或本地输入错误 |
| `4` | 认证错误 |
| `5` | 远端资源、读取、计划或 stale snapshot |
| `6` | 已知 mutation 失败 / partial |
| `7` | 写后确认失败或读取等待超时 |
| `8` | 已发送 mutation 的远端结果未知（indeterminate） |
| `130` | 用户中断 |

自动化不能只看退出码区分 `failed`、`partial` 和 `indeterminate`，必须同时读取 `--json` 结果。

```bash
# 版本 / 帮助
python3 XTF.py --version
python3 XTF.py --help
python3 XTF.py sync --help

# 配置
python3 XTF.py config init --target-type bitable -o config.yaml
python3 XTF.py config validate --config config.yaml
python3 XTF.py config show --config config.yaml

# 自检
python3 XTF.py doctor --config config.yaml
python3 XTF.py doctor --config config.yaml --network

# 计划与执行
python3 XTF.py sync --config config.yaml --dry-run --json
python3 XTF.py sync --config config.yaml --verify-remote-writes --json

# flags-first：不使用 YAML
python3 XTF.py sync \
  --app-id cli_xxx \
  --source-type file --file data.xlsx \
  --target-type bitable \
  --target-app-token app_xxx --target-table-id tbl_xxx \
  --mode full --match-strategy by_key --index-column ID \
  --verify-remote-writes

# 破坏性操作
python3 XTF.py sync --config config-clone.yaml --allow-delete

# 输出控制
python3 XTF.py sync --config config.yaml --quiet
python3 XTF.py sync --config config.yaml --log-level DEBUG
```

Windows 下把 `python3` 换成 `python` 或 `.venv\Scripts\python.exe`。

## 12. 故障排查

| 现象 / 错误码 | 可能原因 | 处理建议 |
|---|---|---|
| `XTF_E_CONFIG_NOT_FOUND` / 退出码 3 | 显式 `--config` 路径不存在，或未生成配置 | 检查路径；用 `config init` 生成 |
| `XTF_E_CONFIG_INVALID` / 退出码 3 | YAML 非法、未知 key、模式组合冲突、缺少 secret | 运行 `config validate`，按提示修正 |
| `XTF_E_INPUT_*` / 退出码 3 | 文件不存在、格式不支持、Excel/CSV 读取失败、表头为空或重复 | 检查输入文件；CSV 可确认 UTF-8/GBK |
| `XTF_E_AUTH` / 退出码 4 | app_id/secret 错误、权限不足 | 检查凭据与飞书应用权限 |
| 退出码 5 / `XTF_E_STALE_SNAPSHOT` | 计划后目标被他人修改、分页读取不完整 | 重新读取目标状态，重新生成计划；不要直接重跑写入 |
| `XTF_E_DELETE_CONFIRMATION_REQUIRED` | 模式或计划包含删除/清空 | 审核计划后显式加 `--allow-delete` |
| `XTF_E_CONFIRMATION_TIMEOUT` / 退出码 7 | 写后读回在时间窗内未看到预期值 | 先读目标；确认实际状态后再决定是否重跑 |
| 退出码 8 / `indeterminate` | 写入请求已发出但响应丢失或结果未知 | 先读目标，禁止盲目重放 |
| 错误码 `1254290` 等限流 | 触发飞书频控 | 降低 `batch_size`、增大 `rate_limit_delay`、启用 `control.advanced` |
| `config validate` 报缺少 secret | 模板中 `app_secret` 为 null | 设置 `XTF_APP_SECRET` 或传 `--app-secret` |
| 公式保护被拒绝 | 非 `full`、缺少索引列、索引列是公式列 | 调整模式/索引列，或关闭 `protect_formulas` |
| Sheet 写入结果未知 | append 缺少可证明的实际落点、AI 返回 partial | 读取目标后再决定下一步，不要自动重放 |
| `.xls` 读取失败 | 当前引擎不支持旧格式 | 另存为 `.xlsx`，或确认 Calamine 可用 |
| Base v3 / Sheet AI 接口报错 | 该能力主要来自官方 CLI 的扩展协议，租户可用性未在本工具内证明 | Bitable 目标可显式切换 `bitable_v1`；公式验证需先确认租户能力 |
| `ModuleNotFoundError` / pandas 版本不符 | 系统环境不满足 `pandas<3` | 使用项目 `.venv` 安装 `requirements.txt` |

## 13. 安全清单

- 正式操作前先备份目标表/工作表；`overwrite` 和 `clone` 会删除远端数据。
- 在隔离的 Base/Sheet 上完成首次验证，再考虑生产资源。
- 永远不要把真实 `app_secret`、`app_token`、`spreadsheet_token`、本地 `config.yaml` 或运行日志提交到 Git。
- 先 `--dry-run` 审核计划，再执行；任何 destructive plan 都要显式 `--allow-delete`。
- 默认成功不代表读回确认；需要确认时启用 `--verify-remote-writes`。
- 收到 `indeterminate` 或超时时，先读取目标状态，不要自动重跑整个任务。
- dry-run、本地测试和 CI 构建都不能替代真实 Feishu UAT。

## 14. 图形界面（可选）

仓库附带一个面向非技术用户的 Tkinter 桌面界面，位于 [gui/](../gui/)。它不重新实现同步逻辑，而是生成 YAML v2 配置并调用本页的 CLI。

启动方式（Windows）：

```text
双击 gui\launch_gui.bat
```

或命令行：

```bash
python3 gui/app.py
```

界面流程：

1. 填写 App ID / App Secret，粘贴 Base 链接；点“解析”后在下拉框中选择数据表（不需要另开窗口）
2. 选择 Excel / CSV，查看预览和列映射
3. 自动检查唯一索引列；没有唯一 key 时只允许“只追加”
4. 自动排除公式、查找引用等只读列
5. 先生成 dry-run 预览，再执行；危险模式需要二次输入“删除”

界面布局：

- 步骤 3 的表单内容较长时可以滚动，底部“生成预览”按钮始终固定可见。
- 模式说明只显示当前选中项；事实摘要和红色风险提示分行显示，互不影响。
- 切换 `base_v3` / `bitable_v1` 不改变界面布局，只改变底层读取方式。

安全与限制：

- secret 只保存在内存中，不写入配置文件；可以从 `config.yaml` 载入但不显示。
- 界面目前只支持多维表格（Bitable）；Sheet 请使用 CLI。
- 没有内置定时任务；需要定时同步请使用 Windows 任务计划程序或 CI。
- 详细说明和打包注意事项见 [gui/README.md](../gui/README.md)。
